# 個人情報・問い合わせ情報の漏えい等が疑われる場合の対応メモ

Postfolio の運営中に、個人情報、問い合わせ内容、添付画像、決済識別子、保存投稿データなどの漏えい・滅失・毀損・不正アクセスが疑われる場合の初動メモです。

この文書は運営者向けの実務メモです。実際の判断が難しい場合は、個人情報保護委員会の案内や専門家へ確認してください。

## 1. まず止血する

- 該当機能、該当API、該当アカウント、該当環境変数の利用を一時停止する
- Resend、Stripe、OpenAI、データベース、ホスティング環境の管理画面で不審な操作履歴を確認する
- APIキー、Webhookシークレット、DB接続情報などの漏えいが疑われる場合は、速やかにローテーションする
- 追加被害を防ぐため、必要に応じてアプリをメンテナンス表示に切り替える

## 2. 事実確認を記録する

- 発覚日時
- 発覚経路
- 影響を受けた可能性のあるユーザー数
- 影響を受けた可能性のある情報
- 原因の仮説
- 実施した停止措置、復旧措置
- 外部サービス側で確認したログ

## 3. 対象情報を分類する

- アカウント情報: メールアドレス、表示名、アイコン画像
- 投稿管理情報: 保存URL、タイトル、本文、画像、メモ、タグ、コレクション
- AI関連情報: AI分析結果、AI分析に送信した投稿情報
- 問い合わせ情報: 名前、返信先メールアドレス、件名、本文、添付画像
- 課金関連情報: Stripe顧客ID、契約ID、Price ID、契約状態

カード番号そのものは Stripe が処理し、Postfolio 側では保存しない想定です。

## 4. 報告・通知の要否を確認する

漏えい等の内容によっては、個人情報保護委員会への報告や本人通知が必要になる場合があります。

確認観点:

- 要配慮個人情報が含まれるか
- 財産的被害が生じるおそれがあるか
- 不正アクセス等によるものか
- 影響人数や影響範囲が大きいか
- 本人へ速やかに知らせる必要があるか

判断に迷う場合は、個人情報保護委員会の案内を確認し、必要に応じて専門家へ相談します。

## 5. ユーザーへ通知する場合の内容

- 発生または発覚した日時
- 対象となる可能性のある情報
- 現時点で分かっている原因
- 実施済みの対策
- ユーザーにお願いしたい対応
- 問い合わせ先
- 今後の再発防止策

不確定な情報は断定せず、「現時点で確認できている範囲」として伝えます。

## 6. 復旧後に行うこと

- 原因箇所の修正
- 権限、環境変数、外部サービス設定の見直し
- ログ監視、通知設定の追加
- プライバシーポリシーや利用規約の更新が必要か確認
- 再発防止策を記録する
