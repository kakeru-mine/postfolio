# 多言語化（i18n）方針

Postfolio の英語対応の現状・運用ルール・今後の移行方針をまとめます。

## 現状の仕組み

英語表示は **DOM 翻訳レイヤー** で実現しています。

- `src/components/language-dom-translator.tsx` が、`<main>` 内のテキストノードを走査し、
  **ノードのトリム後テキストが辞書キーと完全一致したとき**に英訳へ差し替えます。
- ヘッダー / フッターなどのチャクラ（`<main>` の外）は、`src/components/app-shell.tsx` の
  `labels`（ja / en）で個別に英語化します。
- 言語状態は `localStorage("postfolio-language")` と `<html lang>` で共有されます。
  - 切替 UI：`app-shell.tsx`（アプリ内）/ `standalone-language-controls.tsx`（規約・お知らせ等の単体ページ）

## 🔴 運用ルール（当面・必読）

新しい文言を追加・変更するときは、**必ず同じ変更内に翻訳も含める**こと。

1. **新規の日本語UIテキストを足したら、`language-dom-translator.tsx` の辞書に
   完全一致のエントリを追加する。** 追加し忘れると、その箇所だけ英語モードで日本語のまま残る。
2. **キーは表示文字列と1文字単位で一致させる。** 助詞違い（「に」/「へ」）、句読点、
   言い回しの変更でマッチが壊れる。日本語を直したら辞書キーも直す。
3. **`<main>` の外（ヘッダー/フッター等）の文言は `app-shell.tsx` の `labels` に
   ja / en 両方を追加する。** 辞書ではなくこちらが対象。
4. **動的・ユーザー投稿テキスト（DBコンテンツ・日付）は辞書では翻訳できない。**
   `announcement-translatable.tsx` のように **ja / en を props で受け取るクライアント
   コンポーネント**で描画し、英語値はデータ生成元（例：投稿時の OpenAI 翻訳）で用意する。

### レビュー時チェックリスト
- [ ] 追加/変更した画面を **English に切り替えて**、日本語の残りがないか目視確認した
- [ ] 文言を変更した場合、対応する辞書キー / `labels` も更新した
- [ ] 動的テキストは ja / en を両方供給しているか

### 開発時の自動チェック（堅牢化）

`language-dom-translator.tsx` には、**開発モードかつ English 表示のとき**だけ動く監査が入っています。

- `<main>` 内に残った「辞書エントリの無い日本語テキスト」を検出し、`console.warn` で一覧表示します。
- 翻訳漏れ（登録忘れ・助詞ズレなど）を、その画面を英語で開いた瞬間にコンソールで気づけます。
- **本番ビルドでは動きません**（`NODE_ENV !== "production"` ガード）。

#### 動的・ユーザー投稿テキストの除外
DBコンテンツ・日付など、辞書ではなく ja / en の値を自前で持つ要素は、
ラップ要素に **`data-i18n-dynamic`** を付けると監査対象から外れます。
（例：`announcement-translatable.tsx` の `TranslatableTitle` / `TranslatableBody`）

```tsx
<span data-i18n-dynamic>{/* 自前で ja/en を切り替える動的テキスト */}</span>
```

→ 新しい画面を英語で開いてコンソールに `[i18n]` 警告が出たら、
辞書に追加するか `data-i18n-dynamic` で除外する、を徹底すれば翻訳漏れを防げます。

## 今後の移行方針（next-intl 等）

DOM 翻訳方式は「文言が増えるほど登録漏れで壊れやすい」という構造的な弱点があります。
英語対応を本格的に継続するなら、**メッセージカタログ方式（`next-intl` など）への移行**を推奨します。

移行は影響範囲が全画面に及ぶため、**一括ではなく段階的**に進めます（想定）。

1. 基盤導入：`next-intl` のプロバイダ設定、`messages/ja.json` `messages/en.json` の用意、
   言語の保持方法（cookie ベース）を決定。
2. 共通チャクラ（ヘッダー/フッター/ボタン）から `t("key")` 方式へ置換。
3. ページ単位で順次移行し、移行済みページは DOM 翻訳辞書から除外。
4. 全ページ移行後に `language-dom-translator.tsx` を撤去。

> 移行着手の判断は、英語ユーザーの比率・追加予定の画面数を見て決める。
